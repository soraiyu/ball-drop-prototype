# ball-stream GCP 時間貸しデモ ランブック

目的: OCI A1 の空き待ち（宝くじ）を止めずに、ボール配信パイプラインの
実地検証を先に終わらせる。VM はデモの間だけ作って、終わったら必ず消す。

## 構成物
- `stream_live.py` — Pymunk 物理＋PIL描画＋ffmpeg のライブ配信用。
  実時間ペーシング付き。RTMP_URL があれば YouTube Live へ、無ければ
  ローカルファイルへ出力（性能テスト用）。ボールは CLEAR_AT（既定100）
  個で一斉クリア。ローカル検証済み: 6秒・180フレームを 29.9fps で
  描画＋エンコード、CLEAR_AT の動作も確認済み（2026-10-28）。
- `startup.sh` — VM 初期セットアップ（ffmpeg / venv / pymunk 等）。

## VM スペック（承認済みの見積もり範囲）
- asia-northeast1（東京）、e2-standard-2（2 vCPU / 8GB）、Ubuntu 22.04
- ディスク 20GB、Spot は使わない（数時間の差額は数円、安定優先）
- 単価 $0.086/h（2026-10-25 調査）。想定: 準備0.5h＋配信2h＋後片付け
  0.5h ＝ 3h で約 $0.26、ディスク等を含めても約 $0.30 ≒ ¥45
  （$1=¥150 換算）。YouTube への egress は Google 公式料金で無料。
- 最大の課金リスクは消し忘れ。デモと同一セッション内で削除まで完了し、
  削除をふわが確認して報告する。

## 実施形態（2026-10-31 決定）
今週末（10/31土〜11/1日）の1セッションで、ステージA（性能テスト）
からステージB（実配信）まで一気に通す。所要は準備込みで最大3時間、
課金もその範囲（約¥45想定）に収める。

## 実施結果（2026-10-31）と学び
- 性能テスト合格（30.0fps）、同日夜に実配信まで実施し、ユーザーが
  りつねぐでボール落下を確認。VM・ディスクは同日夜に削除済み。
- 起動は run_live.sh（キー入力プロンプト）経由だと tmux 下で即死した。
  RTMP_URL を環境変数で直接渡す方式は安定。次回も直接方式で。
- 終了済みの配信には再接続しても Studio で「オフライン」のまま
  開始できない。配信は毎回新しく作り、必要ならキーも新規発行する。
- Studio のモバイル Web はプレビューが表示されないことがある。
  接続状態（非常に良い）と公開側の表示で判断する。
- ストリームキーをチャットで受け渡した場合は、終了後に Studio で
  キーをリセットする。

## コメント連動（2026-10-31 実装）
- 実装：`chat_triggers.py`（ポーリング方式）＋ `stream_live.py` の
  `CHAT_MODE=youtube|mock`。モックで検証済み（29.9fps、判定・
  クールダウン・色指定OK）
- GCP プロジェクト ball-stream-demo で YouTube Data API v3 有効化済み
- 残作業（チャンネル所有者の操作が必要）：
  1. OAuth 同意スクリーン＋デスクトップ用クライアントを用意する
  2. クライアント JSON を VM（または実行マシン）に置き、
     `YT_CLIENT_SECRET_FILE` にパスを指定する
  3. 初回起動時にブラウザで認可する（youtube.readonly のみ）。
     以後は `yt_token.json` で自動更新される
  4. 配信を開始してから `CHAT_MODE=youtube` で起動する
     （アクティブな配信の liveChatId を自動で引く）
- トークンとクライアント JSON は Git に入れない（.gitignore 済み）

### 実チャット検証（2026-11-01 夜）— 成功

  VM にコードとトークンを配置し CHAT_MODE=youtube で配信、

### ストリーム形式＋協力型ゲーム（2026-11-01 実装）
- streamList は gRPC（公式ガイド準拠）。stream_list.proto から
  生成した stream_list_pb2.py / stream_list_pb2_grpc.py を使用。
  CHAT_MODE=youtube がストリーム形式、youtube-poll が従来方式。
  ハンドラ単体テスト済み、実地検証は次回配信時
- 協力型ゲームを stream_live.py に実装：HUD進捗バー（要
  fonts-noto-cjk）、目標到達で金色ボール（半径44＝ピン間隔を
  通れる上限付近）＋ミニボール10個、バナーは金文字＋濃色縁取り
  （金ボールと同色で読めなくなるため）。モックで目視確認済み
- VM へは stream_list_pb2*.py も配置すること（startup.sh 更新済み）

### アヒル＋登録者お祝い（2026-11-02 実装）
- 白いアヒル（PIL図形描画）を stream_live.py に実装：床を歩行、
  チャットボールで小ジャンプ、ゴールで「やった！」、新規登録で
  「ようこそ！」吹き出し。物理ボディなし（視覚のみ）
- subscriber_watch.py：SUBS_MODE=on|mock。channels.list 統計と
  subscriptions.list（mySubscribers）を SUBS_POLL_SEC 間隔で確認。
  実トークンで読み取り確認済み（登録者1人・非公開のため一覧は空
  ＝匿名お祝いになるケース）。seen_ids は seen_subs.json に永続化
- 学び：金色ボール半径44はピン列ピッチ（90）と干渉して列間に
  楔止めされ永久に落ちなかった。半径34（直径68）で解消。
  保険として「5秒落ちない大ボールへの横押し」も残してある
- バナーはキュー化（同時イベントで消し合わない）
